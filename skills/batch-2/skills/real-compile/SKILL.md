# Compile

## The contract (see references/responsibility-matrix.md)

**Input: the finalized `reel.json` from `/real-storyboarding` — the single
authoritative editorial handoff.** `story.json` is internal: generated by
`adapt.py`, regenerated every run, never hand-edited, never requested from
anyone. This skill makes **no editorial decisions** — not which visual goes
where, not where audio goes, not what text says, not whether a text element
is a title, caption or subtitle. It translates, validates, resolves paths and
exports; when the reel is ambiguous, it refuses with a message naming what
/real-storyboarding must settle, and never fills the gap itself.

Two guarantees the build enforces:

- **Text arrives classified.** Every text layer carries `style` — title,
  caption or subtitle (lower-third, kicker, word also accepted) — and each
  maps to its own distinct FCP styling. A missing or unknown style is a
  refusal, not a default: an unclassified text element would export as the
  wrong kind of thing.
- **Parity, or refusal.** Every storyboard layer and audio lane must be
  represented in the output. The build prints a parity line (layers in →
  elements out, audio lanes in → connected clips out) and **refuses** if
  anything was dropped — the creator-approved storyboard and the exported
  timeline must not describe different videos.

Last step of the REAL pipeline:

`/real-brainstorm` → `/real-create-catalogue` → `/real-storyboarding` → **`/real-compile`**

The creator is not supposed to understand this step. They call it, they get a
file, they import it into Final Cut Pro and finish the edit by hand. Everything
you say to them should be in those terms — a file, where it is, what to do with
it, and what still needs their eye. The internals below are for whoever
maintains the skill.

**The input is `reel.json` and nothing else** — written by
`/real-storyboarding`, the whole plan: what is on screen at each moment, what is
under and over it, what is heard, and when. Spec in `spec/reel-schema.md`.

**If there is no `reel.json`, refuse.** Do not propose a sequence, infer one
from an assets folder, or "start something to look at". Say the storyboard
hasn't been made yet and point at `/real-storyboarding`. This skill never
decides what goes where; that split is why pacing can be approved once and stay
approved.

## The approval gate — the report first, the file only on a go-ahead

Deliver `report.html` — the lane-by-lane timeline strip with real timecodes,
read straight out of the built file — and **stop**. The creator vetoes the
sequencing there, without opening Final Cut. Only an explicit go-ahead moves you
to delivering the export; shipping both in one pass wastes their veto even when
it validates clean.

## The loop

**1. Adapt.**

```
python3 scripts/adapt.py reel.json -o story.json
```

`story.json` is an internal intermediate — nobody authors it, and it is
regenerated from the reel every time (`references/story-schema.md`, maintainers
only). `adapt.py` maps beats onto the primary storyline, layers by `z` onto the
backing clip plus connected overlays, audio lanes onto connected clips with
ducking envelopes, and writes a real placeholder file for every stub so the
import has grey holes instead of red missing media. Beat names, narration and
`moment` travel into the clip's Notes and a timeline marker.

**`adapt.py` refuses, with a numbered list, rather than guessing.** It never
fills in a default silently and — the one that matters — **it never computes a
time.** The clock belongs to `/real-storyboarding` and exactly one
implementation of it exists. A second estimator produces timings that look
coherent and are wrong, which reads as an editorial problem rather than a
measurement fault; that already cost a 59-second error and a page of
unnecessary cut-list. A reel with no times is a refusal, not a thing to compute.

Audio lanes are `narration | source | bed | sfx`. `source` means a clip's own
sound — the demo you are meant to *hear*, which is the whole point of a demo
beat — and it is normal for the same movie to be both a video layer and a
`source` lane. Picture and sound are stated separately, so every video layer's
own audio comes in at −60 dB and the lanes say what is actually heard; one
click in Final Cut restores any of it.

**2. Build and check.**

```
python3 scripts/compile.py build story.json timeline.fcpxml --target fcpxml
python3 scripts/compile.py report timeline.fcpxml report.html
```

`build` validates and refuses to call a file with errors deliverable.
`validate.py` catches what Final Cut would only tell you by refusing: frame
misalignment, dangling refs, stills placed as `asset-clip`, anchored offsets in
the wrong timebase, children out of DTD order, clips reading past the end of
their source. **Never deliver a file with errors.** "Not found from here"
warnings are expected when the footage only lives on the Mac.

**3. Deliver the report, take the veto, then the file.** The `.fcpxml` imports
with **File → Import → XML…**.

**4. Revise.** The creator answers in edit language — "hold B3 longer", "lose
the caption on B4". Those are storyboard changes: back through
`/real-storyboarding`, which reissues `reel.json`; re-adapt and rebuild. The
`.fcpxml` and `story.json` are disposable, `reel.json` is the artifact.

## Where the file goes

`assets_root` is the folder path **as the Mac running Final Cut sees it** — it
is baked into every clip. `assets_root_local` is where those files are reachable
from wherever you are running, and is used only for probing. Getting
`assets_root` wrong is the one mistake that makes an import look like it worked
and then show red Missing Media.

**The desktop bridge belongs to the machine the session started on** — it
does not follow the creator across devices. If Final Cut is on the iMac, the
session that builds and delivers must start on the iMac; otherwise work from
attached JSONs and declared metadata (legitimate — the schema carries
durations and dimensions precisely so a build can run where the footage
isn't; what you lose is verification, so say which case you're in).

**Write the `.fcpxml` straight into the folder the media lives in.** Do not
rely on the creator downloading it and running a path-fixer: browsers rename a
repeat download to "folder 2", "folder 3", so any path baked relative to the
original folder name silently breaks and every clip imports red. Prefer building
on the machine that holds the media.

If media does show up red, it is a path problem, not a format problem:
`python3 scripts/retarget.py timeline.fcpxml /new/root` rewrites every source
path in one pass and reports what it couldn't find.

## Compiling before the voice exists

**This is the normal case, not a degraded one.** A narration lane with no take
yet (`asset: null` plus the line in `text`) is what a reel looks like before
recording, and the whole two-clock design depends on it: the creator sequences
the reel on the estimated clock, sees it, fixes it, and only then reads it
aloud. Refusing to compile without a voice track would invert that — the point
of compiling early is finding out a 60-second reel is 34 seconds over *before*
spending an afternoon recording it.

So every unvoiced line becomes a real silent clip in the narration lane at
exactly its planned window, named with the words that belong there, and the
export is badged **UNVOICED** — in the build output, in `report.html`, and in
the Final Cut project name itself. Say it plainly when you deliver: *the timing
is real, and it is estimated, not measured; record the voice and the measured
clock replaces it without moving anything you approved.* Only a narration lane
with no take **and** no line is a refusal — nothing holds that window open.

## Voice — the measured clock

When real takes exist, the recording is the clock and the estimate was only ever
a stand-in.

```
python3 scripts/voice.py script   reel.json -o narration.txt
python3 scripts/voice.py assemble takes.json -o master.wav
python3 scripts/voice.py measure  --script narration.txt --audio master.wav -o measured.json
python3 scripts/voice.py delta    reel.json measured.json
```

`assemble` splices sequential takes and retake patches with 12 ms crossfades
(click-free) and compresses dead pauses. `measure` force-aligns the narration to
the assembled track and emits `measured.json`, a word-index → timestamp map.
This is what turns an UNVOICED export into a measured one.

**Alignment re-times. It does not re-plan.** Every placement upstream is
anchored to a word index, so when the measured clock swaps in the words move and
the placements do not — nothing is re-chosen or re-fitted. The swap itself
happens in `/real-storyboarding` (`clock.py swap`), because there is exactly one
implementation of the clock; this skill hands back `measured.json` and a report.

**But nothing gets absorbed quietly.** `delta` prints the estimate-to-measured
difference per beat, in seconds. If a section has drifted far enough that the
pacing the creator approved no longer holds, say which sections moved, in their
terms — "the demo runs a second longer than planned" — and offer to send them
back to `/real-storyboarding` to re-fit it. Do not silently re-time an approved
reel and do not write times back into `reel.json`.

Alignment failing almost always means the words spoken are not the words
planned. Free-transcribe the region (`align.py transcribe clip.wav`) to find out
what was said, then fix the script or the take — never paper over it by shifting
times.

## Targets

The export format is a parameter. `--target fcpxml` is the default and the only
one implemented; `compile.py targets` prints the registry. Adding Premiere XML,
an EDL, Remotion or CapCut is one module in `scripts/targets/` plus one line in
its `REGISTRY` — interface and a worked stub in `references/targets.md`. Nothing
in the sequencing side (`adapt.py`) knows about output formats. Keep it so.

## When Final Cut rejects an import

Work down `references/fcpxml-notes.md` — **six** things break imports; the
sixth is a `/` or newline in any name ("You may not use '/' or the return key
in names"), which fires BEFORE media resolution and so masquerades as a
corrupt file. `fcpxml.py` now sanitizes every name centrally in `El.set()`
(`/` → `·`, newlines stripped); if that error ever appears, the file came
from an old generator.

Otherwise, in order of likelihood:
In order of likelihood: a still placed as `asset-clip`, a time off a frame
boundary, an anchored offset computed in sequence time instead of the parent's
timebase, a dangling `ref`, a bad `file://` path.

FCP DTD-validates on import, so a rejection quotes the exact content model it
expected — read it, fix the order or the element, done. The known soft spots are
under "Confidence" in the same file: the Cross Dissolve `uid`, keyframed
`adjust-volume`, `srcEnable="audio"`, and the `<note>`/`<marker>` metadata
(strip it with `adapt.py --no-markers`). Each degrades locally.

The permanent fix for any disagreement with Final Cut is a diff: build the shape
by hand once in FCP, export XML, compare it against what the generator writes,
and fold the answer back into `references/fcpxml-notes.md`.

## Rules of the house

- **Bias every choice toward editability.** Real title clips over burned-in
  text, connected clips over flattened audio, named beats over anonymous ones.
  The point of exporting a timeline rather than a video is that the creator
  keeps the edit.
- **Rendering an mp4 is out of scope.** The pipeline ends at the timeline; the
  editor does the rest. If asked for a finished video, say so.
- **No `/` and no newlines in any name** — sanitized centrally in
  `fcpxml.py`'s `El.set()`; keep it that way if you touch the generator.
- **U+202F filenames need no renaming for Final Cut** — the verbatim
  character in a `file://` URL (`%E2%80%AF`) resolves fine; only *staging*
  chokes on it (and the catalogue step now renames these at the source).
- **Rotation flags (`rot-90`/`rot-180`) are verify-at-import items** — assume
  honored, say so at delivery, offer to bake the rotation in if footage comes
  in sideways.
- **Never source or generate content media.** A missing asset is a stub with a
  spec, or a numbered request — never an improvisation.
- **Blanks are deliberate or defects.** Every gap `adapt.py` emits is named.
- If a script hits an edge case, fix the script rather than hand-patching the
  XML, so the fix survives to the next reel.

## Scripts

- `scripts/adapt.py` — `reel.json` → `story.json`, plus placeholder files.
  Refuses on anything incomplete; never invents a time.
- `scripts/compile.py` — `build` / `validate` / `report` / `targets`, per target.
- `scripts/targets/` — the registry; `fcpxml_target.py` is the one entry.
- `scripts/fcpxml.py` — the verified FCPXML generator (`build`, `probe`,
  `schema`). All timeline math is integer frames. **Port it, don't rewrite it.**
- `scripts/validate.py` — semantic checks, optional `--dtd`. Non-zero on errors.
- `scripts/report.py` — the HTML timeline strip, read from the built file.
- `scripts/retarget.py` — repoint every media path at a new root.
- `scripts/voice.py` — `script` / `assemble` / `measure` / `delta`.
- `scripts/align.py` — forced alignment and free transcription (pocketsphinx,
  model bundled in the wheel, works offline). `--oov` for music vocabulary.
- `scripts/audio.py` — crossfade concat, pause compression, ducking envelopes.
