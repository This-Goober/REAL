# REAL local-correction walkthrough

This two-minute demonstration uses development seed 1's existing notebook and
synthetic media. Its words and images are placeholders. Timing is **estimated**;
there is no recorded narration and no model call. It illustrates an interaction
contract, not artistic quality, usability, or new benchmark performance.

Build from the repository root with Python, Pillow, NumPy, and FFmpeg installed:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 demo/build.py \
  --out bench/work/himas-demo --pool bench/work/pool
```

Use a new output directory each time. In the research artifact, the pool is
`artifact-data/synthetic-pool`. The resulting `index.html` opens from disk and
links the original production tracks pages, export reports, and FCPXML files.
Thumbnails are embedded; the preview does not play continuous video or audio.

## Presenter script

| Time | Show | Say or do |
|---|---|---|
| 0:00–0:20 | `index.html` | “REAL represents the edit as inspectable placements. This is a synthetic timing example, with no recorded narration.” |
| 0:20–0:45 | Before tracks, click `B4.L3` in beat 4 | “This is image img07. I can inspect its source, selection explanation, and insertion word: nickel.” |
| 0:45–1:05 | Scroll to the selected layer's details below the preview, then the anchor field | Type `velvet`, then click **copy revision block**. “I specify the word I mean. The page records the correction; applying it is a separate rebuild.” |
| 1:05–1:30 | After tracks, click `B4.L3` | “The same image now lands on velvet. Its requested duration stays 0.8 seconds, and the choice is marked as the creator's.” |
| 1:30–1:50 | Comparison table and export reports | “The independent XML reader finds 15 other placements with unchanged identities and boundaries. A further build with creator choices preserved keeps the new anchor.” |
| 1:50–2:00 | FCPXML links | “The result is an editable project. This check is about timing and identity; native rendering and creator benefit require separate evaluation.” |

The after-state is actually generated by `revise.py`, `adapt.py`, and
`compile.py`. It is not simulated by the landing page. `verification.json`
records the exact exported frame boundaries and scope of the comparison.
`commands.json` records the commands and validation output. The demo also runs
`build.py build --preserve` and checks the creator's asset, word anchor,
duration, ownership and derived times.

## Optional Final Cut recording

The creator handles Final Cut. Import one of the generated `timeline.fcpxml`
files with **File → Import → XML**, inspect beat 4, then compare the other state.
Both exports are unvoiced and have the same project title; keep them clearly
labelled in the library if importing both. Record native import only after it
succeeds; the build's structural validation does not establish that result.

Keep the generated folder in place: the XML points to its local media. To use
another machine or folder, rebuild there from this script and the included
synthetic pool. Do not claim audible word alignment from this silent example.

## Relationship to the paper

The paper's 30 local-repair results use synthetic supplied word times. This
walkthrough instead selects the production estimated-clock mode, making its
unrecorded status explicit. It adds an inspectable illustration, not another
sample to the reported experiment or evidence of participant performance.
