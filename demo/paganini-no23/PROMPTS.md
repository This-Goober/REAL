# The prompts that produced this demo

Everything in this folder came from the exchanges below between the creator
and the REAL assistant (Claude) on 19, 23 and 24 October 2026, in the order given. The
creator's requests are quoted verbatim; what each produced is summarised
underneath, with the command that reproduces it from this folder. Earlier
steps (the earlier edit this demo starts from) are summarised at the end.

## 1. The OpenTimelineIO export must show its captions in Resolve

Context: the creator had imported the binary-search demo's `.otio` into
DaVinci Resolve. Everything imported except the captions, which Resolve showed
as red "unknown media" clips of the right length, because OTIO has no title
type and Resolve has no renderer for an unknown generator. Three options were
offered: draw each caption to a transparent PNG still, a Resolve script, or
leave placeholders.

> really how can a video format not supporting a text type? I see in davinci
> resolve it can drop a text

> you can create me one with #1 to test is fine.

Produced: the `--titles raster` mode of the `otio` compile target
(`skills/batch-2/skills/real-compile/scripts/targets/title_raster.py`), which
draws each text layer with the requested font, size, colour, glow, shadow and
position to a PNG at the sequence size and references it as a still; the
words and styling stay in the clip's metadata so the independent reader still
checks them. Documented in `references/targets.md`.

## 2. Rebuild the tutorial on the studio footage, with more captions and a closing clip

> ok next I want to improve the paganini no 23 tutorial using a newer video
> that I just reproduced. The original video had the bedroom background and I
> have used bitrefnet to remove the background and replace it with a more
> studio background with band 10% at the bottom which looks nicer. the video
> should be in the /tmp/paganini_no23_fingering_studio.mp4, this time make
> slightly more captions (as in more places) and the Font 55 size and use Glow
> and make sure the width does not go over use the multi-line as you need to
> also generate the .otio versions. Also at the end I want to append the
> /tmp/paganini_no23_closure.mov.

Produced: `scripts/build_timelines.py`. It starts from the approved earlier
storyboard (`source/storyboard.json`, `source/word-clock.json`), verifies the
studio recording is the same audio sample for sample (so every source window
and word anchor carries over), swaps the five excerpts, adds six captions at
creator-chosen words with the clock's text-model durations, appends the
closing clip as a wordless beat, and compiles to FCPXML and OTIO with the
cross-target check. The closing clip was cropped once to 9:16 so neither
editor needs a transform (`scripts/cut_excerpts.sh`).

```sh
cd demo/paganini-no23
sh scripts/cut_excerpts.sh /path/to/paganini_no23_fingering_studio.mp4 /path/to/paganini_no23_closure.mov   # only if re-cutting
python3 scripts/build_timelines.py --from-dir source --media-root media --out timeline --no-publish --public --name paganini-no23 --title "Paganini No. 23 tutorial"
```

## 4. Export both editors at the same geometry

> both are good. I want to export the actual video generated by davinci
> resolve how do I do it to make sure the resolution is the same as exported
> as final cut pro then I want to do comparison side by side.

Steps given and followed (Resolve 21, free; Final Cut Pro 11):

- Resolve: new project; Project Settings → Master Settings → timeline
  resolution Custom 1080×1920, frame rate 30, "Scale entire image to fit";
  File → Import → Timeline → the `.otio` (do not let the import change the
  project settings); Deliver → Custom, QuickTime H.264, 1080×1920, 30 fps,
  audio AAC 48 kHz.
- Final Cut: File → Import → XML → the `.fcpxml`; File → Share → Export File,
  Video and Audio, H.264 Better Quality, 1080×1920.

## 5. Measure the two renders

> ok done and I want to do side by side comparison measuring the two can you
> schedule running the comparison
> ~/Downloads/paganini-23-STUDIO-v5-davinci-resolve.* and "Paganini 23 — by
> REAL v5 - finalcutpro.mov". The goal is to give a good agreement that .otio
> and .fcpxml and so far to human eyes they look almost identical apart from
> font maybe slightly different

Produced: `scripts/compare_exports.py` and `comparison/`. It reads both
exports at the timeline rate, detects every cut and every caption edge against
the timeline's own event list, measures the caption glyph boxes on
full-resolution frames, computes SSIM and PSNR per frame, checks audio lag and
level, and writes the three-panel analysis movie (A | B | difference ×4).

```sh
python3 scripts/compare_exports.py "FINALCUT-EXPORT.mov" "RESOLVE-EXPORT.mp4" timeline/timeline.otio comparison
```

## 8. Three narration trims

> I want to fix the narration -- take 02.wav there is a "hallo we all know".
> The first few seconds where it says ".... we all know" should be cut. Also
> take 03-04.wav transition is not smooth. The beginning 0.5 sec of 04 sounds
> also like a blip noise.

Produced: `source/narration-trims.json`, the three trims as data, and a step
in `scripts/build_timelines.py` that applies them before anything else. A trim
moves a beat's source window by whole frames; the words outside the window
leave the clock, the remaining words are renumbered, every caption and still
keeps its anchor word, the beat's base shot and narration move to the new
first word, and the beats that follow move up by the time removed. The build
refuses a trim that would cut a word a caption or still is anchored to.

- Beat 2 starts 75 frames later, on "for example"; "So we all know that" is
  gone, with the cut in the pause before "for".
- Beat 3 ends 11 frames earlier. Its window had run into the next word
  ("because"); it now ends in the closure before it, after "smaller".
- Beat 4 starts 17 frames later, just before "interval". The first half
  second held a word fragment ("the") and a click.

The three excerpts and their narration takes were re-cut at the new windows
(`scripts/cut_excerpts.sh`, 12 ms fades on the edges that fall inside speech),
their audio checked against the earlier recording at the declared offsets
(0 ms lag). The tutorial is 103 frames shorter: 2644 frames, 88.1 s. All
eleven captions keep their anchors; both timelines rebuilt, 0 errors,
21/21 events equivalent across the two targets.
